Does tool RL make a model worse without the tool?

1.5B math models on AIME: what happens when ToRL loses its Python interpreter.

Steven Li · October 15, 2026

Setup

One base model, three checkpoints

BaseQwen2.5-Math-1.5B, no RL
Text RLOat-Zero: RL on math, no tool. The control.
Tool RLToRL: RL with a Python interpreter

Tool RL minus text RL separates what the tool did from what RL does on its own. All three checkpoints are public; nothing is trained in the pilot.

Result 2

ToRL leads with the tool and trails the control without it

ToRL minus Oat-Zero, pass@1: +5.1 points with the tool [+0.3, +10.3]; −4.9 denied [−8.7, −1.8]; −3.9 told not to code [−7.4, −1.0]. Same direction at pass@64: +13.3 with the tool, −6.7 denied (interval crosses zero).

With the backtick blocked, ToRL writes Python without the fence and repeats it until the budget runs out: 99% of its truncated samples end in a repeated tail. The ban measures that loop, not ability.

So far

Tool dependence, not lost skill

What we found

With the tool ToRL is the strongest of the three. Without it, it trails the RL control in every tool-off condition. Its arithmetic is fine: it delegates almost every computation and, when the tool is gone, often asserts the answer instead of working it out.

Next

Redirect the model into hand computation the moment it opens a code block, and a denial that asks for hand computation. Then a better arithmetic checker, more hard problems, and the 7B CIR model.

Caveats: one size (1.5B); Oat-Zero and ToRL were trained on different data; 60 problems.
