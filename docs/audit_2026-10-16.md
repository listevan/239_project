# Audit, 2026-10-16

Four independent read-only audits of the VerlTool pilot (run `2026-10-16_verltool-1.5b`):
generation harness, statistics and grading, stage-1 data, and design. Per-row evidence and
reproduction scripts were kept in the session scratchpad. Code fixes are in commit ac6905c.

## Stage-2 result (AIME 2022-2025, 120 problems; strict boxed grading)

| arm | pass@1 | pass@16 | unfinished | stopped early | code-like |
|---|---|---|---|---|---|
| base tool_on | .157 | .392 | 18% | 3% | |
| tool_rl tool_on | .163 | .372 | 32% | 21% | |
| base env_denied | .055 | .200 | 19% | 2% | |
| tool_rl env_denied | .051 | .166 | 30% | 20% | |
| base no_code | .039 | .183 | 43% | 4% | 43% |
| tool_rl no_code | .045 | .148 | 52% | 31% | 39% |
| text_rl no_code | .104 | .250 | 22% | 0% | 21% |

- **Positive control failed.** With the tool, tool_rl is not above base (pass@1 +0.006, pass@16
  -0.020, both inconclusive). The VerlTool 360-step tool checkpoint did not gain over its base, so
  its tool-off scores cannot be read as a test of atrophy. Stage-1's gate (tool on vs off for
  tool_rl) could not catch this: the interpreter adds about 10 points for base too.
- Erosion tests (tool_rl vs base, tool off): inconclusive at both conditions (pass@16 about -0.035,
  intervals include zero).
- text_rl rose above base under no_code (+0.06 at pass@1); tool_rl did not.

## Faults found and fixed (ac6905c)

- **Grading credited stray numbers.** Whole-text math-verify picked up "step 3.", a 60-degree angle
  from the problem, numbers in code comments: up to 41% of a tool-off arm's correct rows on
  OlymMATH (no_code pass@64 0.21 vs 0.14 strict). `correct` is now the last complete boxed answer;
  the lenient score is kept as `correct_any`. AIME moved by under 0.01.
- **Verdict overclaimed:** "no erosion" for inconclusive intervals, "tool-specific cost" when the
  gap was text_rl's gain over base, no mention of a failed positive control, uncorrected stars, NaN
  starred. Now: Holm-adjusted bootstrap p-values, above/below only when significant, explicit
  inconclusive, sharpening named, positive control stated first.
- **Harness latent risks** (did not touch the current data): a resume could mix models or settings
  in one arm (now: settings fingerprint per row, commit in meta); SMOKE wrote into the real run
  folder; non-UTF-8 output from executed code crashed the run; a redo never resumed after a crash;
  a code block closed then end-of-sequence was never run or denied (cost base about 5% of tool
  samples); per-round seeds collided above 64 samples; a cut-off final box hid an earlier one.
- **arith_check** false flags on ellipses, approximations and expressions continued from before
  a run.
- Figures capped at the largest k every arm supports.

## Found, not code faults

- **tool_rl stops early on its own:** 20-31% of its samples end mid-sentence before the token cap
  (end-of-sequence token, confirmed from token counts), concentrated past about 2,400 tokens; base
  2-4%, text_rl 0.1%. Present in VerlTool's own training rollouts. Counted as unanswered; the
  summary now reports it as `early_stop_pct`.
- **no_code leaks code:** 39% of tool_rl's and 43% of base's no_code samples contain unfenced
  code-like lines (the ban blocks fences; banned words get spelled through other token splits).
- **text_rl is not text-only:** trained on the same code-inviting prompt without execution, it
  writes code and invents outputs (70% / 59% of training rollouts at step 200).
- **Seeds are shared across conditions,** so arms are paired; compare them with the paired tests.
- **Every model gets the code-inviting prompt;** base scored lower under it than under a plain
  step-by-step prompt in the 2026-10-15 run.
- **Power:** tool-off, only 18-31 of 120 problems are ever solved in 16 samples; detectable
  differences are about 1.5 points at pass@1 and 7.5 at pass@16.

## What the design audit recommends before more compute

1. A tool checkpoint that passes the positive control (tool_rl above base with the tool).
   GAIR/ToRL-1.5B did on 2026-10-15 (AIME24 .27 vs base .12).
2. A plain step-by-step prompt as the primary tool-free measure for every model; keep env_denied
   and no_code as behaviour measures.
3. 64 samples for every arm, one pre-specified primary contrast, Holm for the rest.
